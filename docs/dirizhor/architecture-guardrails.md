# Архитектурные запреты

Этот документ фиксирует ограничения, которые защищают базовую идею проекта.
Нарушение этих правил считается существенным архитектурным изменением и требует
явного решения пользователя.

## Запрещено

1. Давать AI-агенту прямой доступ ко всей корпоративной памяти.

2. Давать AI-агенту прямой доступ к Document Store в обход Director API.

3. Позволять Agent Gateway самостоятельно выбирать и читать документы без
   проверки Auth/RBAC и фиксации `agent_run_context`.

4. Сохранять результат AI напрямую как утвержденное решение пользователя.

5. Менять утвержденное решение без новой версии, нового решения или связи
   `supersedes`.

6. Делать конкретного AI-провайдера обязательной частью модели данных.

7. Хранить корпоративную память только внутри ChatGPT, Codex или другого
   внешнего AI-сервиса.

8. Передавать агентам больше контекста, чем требуется для задачи, если можно
   ограничиться реестром или выбранными объектами.

9. Выполнять чувствительную операцию без audit-события.

10. Смешивать документы, AI-результаты, черновики и утвержденные решения в один
    неразличимый тип данных.

11. Давать UI прямой доступ к файлам хранилища в обход Director API.

12. Делать между AI-агентами неконтролируемый прямой обмен файлами.

13. Помещать raw capability, prompt, содержимое контекста или AI-результат в
    durable queue, логи, traces или audit metadata.

14. Разрешать Gateway произвольный callback URL, неявную смену provider/model
    или второй provider call в рамках одного `agent_run`.

## Требует отдельного подтверждения пользователя

- изменение базового жизненного цикла задачи;
- добавление нового AI-провайдера как обязательной зависимости;
- расширение прав агента на чтение памяти;
- автоматическое сохранение AI-результатов без просмотра человеком;
- автоматическое утверждение решений;
- отключение или ослабление журналирования;
- изменение модели версионирования документов и решений.

## Разрешено в MVP

- использовать один AI-провайдер как первый адаптер, если интерфейс остается
  заменяемым;
- начать с простой ролевой модели прав;
- хранить файлы в локальном файловом хранилище, если интерфейс Document Store
  позволяет позже перейти на объектное хранилище;
- начать с PostgreSQL как основной БД;
- реализовать поиск по реестру до внедрения сложного векторного поиска.

## Проверочный вопрос перед любой реализацией

```text
Это изменение усиливает роль Дирижёра как контролируемой точки доступа
или создает обходной путь вокруг него?
```
