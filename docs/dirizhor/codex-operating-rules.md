# Правила работы Codex в проекте «Дирижёр»

Codex должен считать положения из подтвержденного контекста уже утвержденными и
не возвращаться к их повторному обсуждению без прямого запроса пользователя.

При каждой технической задаче Codex должен:

1. определить, какой модуль системы изменяется;
2. проверить, не нарушает ли изменение основные архитектурные принципы;
3. сохранять модульность;
4. не создавать прямых неконтролируемых связей между AI и корпоративной памятью;
5. использовать API Дирижёра как основной интерфейс взаимодействия;
6. минимизировать зависимость от конкретного AI-провайдера;
7. обеспечивать журналирование операций;
8. предусматривать версионность данных;
9. сохранять обратную совместимость там, где это разумно;
10. перед существенным изменением архитектуры явно сообщать пользователю о
    последствиях.

Главная задача Codex: реализовывать техническую часть системы в соответствии с
архитектурой, разработанной пользователем совместно с ChatGPT.

Окончательное решение всегда принадлежит пользователю.
